## UI 재편 방향 (2026-07-22 사용자 확정, 진행 중)

**진행 중인 결정과 확정 사항은 [UI재편-스펙.md](UI재편-스펙.md)에 계속 적는다 — UI 작업 전에 반드시 읽을 것.** (2026-07-24 기준: 던지기 입력 제거·보드 칸별 +로 작성, 오늘/마감·만기 타일 제거, PC 달력 좌우 절반 고정. 재도입 금지 목록은 스펙 참고.)

사용자가 **노션을 모티브로 UI를 재편**하기로 함. 단 "노션을 그대로 베끼지는 않는다" — 가져올 모티브는 **① 구역이 나뉜 화면, ② 항목을 끌어 옮기는 조작, ③ 세부정보의 '작업 설명' 칸**. 목표 인상은 **"웹앱 느낌을 버리고 프로그램(데스크톱 앱) 같은 느낌"**. 상세 패널은 **지금 방식 유지**(본문이 안 밀리고 오른쪽에 뜸 — 달력을 보면서 상세를 볼 수 있어야 함) + 슬라이드 애니메이션. 색조는 이 방향이 정해진 뒤 결정. 폰 화면도 처음부터 같이 설계. 진행 방식: 여기서 텍스트로 디자인 합의 → 최종 프롬프트를 Stitch에 넣어 시안 → 그 시안을 보고 다시 구현 지시.

## 개발 메모

- 실행: `npm run dev` (포트 5173). 빌드: `npm run build`.
- **제거된 기능 — 다시 넣지 말 것**: 음성 입력(마이크 버튼, 2026-07-18 제거 — 브라우저 음성인식이 기기마다 오작동, 특히 아이폰 사파리 미지원). 사용자가 나중에 "회의록 녹음 → 정리" 기능을 원하니 그때 다른 방식(녹음 파일 + AI 정리)으로 설계할 것.
- 폰(<900px) 상세는 누른 줄 **바로 아래** 인라인으로 열려야 한다 (보드·표·타임라인·달력 공통). 목록 맨 밑에 렌더링하면 안 보이는 버그가 된다 (2026-07-18 수정). 폰 달력은 칸에 색 막대만 + **아래에 선택한 날짜 하나의 목록**(오늘 기본 선택, 칸 탭 → 그 자리에서 내용 교체, 스크롤 이동 없음 — 아이폰 달력식). **달 전체를 아래에 나열 + 탭하면 스크롤 점프하는 방식은 사용자가 "조작감 최악"이라고 해서 제거함(2026-07-19) — 재도입 금지.** 좁은 화면 판정은 src/useIsNarrow.js 공용 훅.
- **폰 규칙 (2026-08-05 정리, index.css 맨 끝 `폰 화면 정리` 블록에 모여 있음)**: ① 폰 상단은 PC 사이드바와 같은 아이콘 줄(`.ptab`, 건수 배지 `.ptab-n`, 현재 화면은 `.on`) + 동기화 점(`.sync-dot`, 누르면 runDiagnostics) — 글자 탭(.tabs/.tab)은 삭제됨. ② 누르는 것은 최소 40px, **입력 글씨는 16px 미만 금지**(아이폰이 포커스 때 화면을 확대한다 — textarea·select·date는 `input` 전역 규칙에 안 걸리니 따로 지정할 것). ③ **hover에만 의존하는 UI 금지** — 폰엔 hover가 없다. 아이콘 버튼은 `.pa-tx` 라벨을 같이 넣고(PC는 CSS로 숨김), `.tl-x`처럼 hover로 나타나던 것은 폰에서 상시 표시. ④ 달력 칸에는 글자를 넣지 않는다 — 칩(`.cal-ev`)도 띠(`.cal-band`)도 색 막대로, 공휴일 이름(`.cal-holname`)도 폰에선 숨김(빨간 날짜 숫자로 대신, 이름은 아래 목록 제목에). **칸 머리(`.cal-cell-head`)는 폰에서 높이 20px로 못박혀 있다** — 여기에 한 줄이 늘면 그 칸만 밀려 이어진 띠가 옆 칸과 어긋난다(2026-08-07 공휴일 이름 때문에 실제로 발생). 칸에 새 요소를 추가하면 폰 규칙도 같이 추가할 것. ⑤ `.panel-actions button`(0,1,1)이 `.pa-ic`(0,1,0)를 이기므로 상세 아이콘 크기는 `.panel-actions .pa-ic`로 잡아야 먹는다.
- 폰은 드래그가 안 되므로 인라인 상세(inline prop)에 **상태 버튼 줄(할일/진행중/완료)** 이 있다 — 보드 드래그와 같은 규칙(완료=completeMemo, 그 외=stage 지정+필요시 reopen). PC 패널에는 안 보인다. 폰에서 상태 조작이 안 되는 개편을 하면 안 됨. → **2026-11-09 상태 버튼 줄 삭제**(사용자 승인 — 상세 정리): 폰 상태 조작은 상세의 ✓ 완료/다시 열기 + 체크로 저절로 진행중. 손으로 진행중 지정은 PC 보드 끌기만 남았다(폰 보드엔 끌어 놓기가 없다).
- **화면 배율 자동 보정 (2026-07-22)**: 넓은 모니터일수록 글씨·여백이 작아 보이는 문제 때문에, 화면 폭에 따라 `body { zoom }`을 단계로 올린다 (1600px↑ 1.05 / 1900px↑ 1.1 / 2300px↑ 1.15). **배율을 이보다 세게 올리지 말 것** — 1.3~1.45로 넣었더니 "그냥 확대해놓은 것 같고 밸런스가 안 맞는다"는 지적을 받아 낮춤. **zoom은 반드시 body에** — `html`(:root)에 걸면 미디어쿼리 판정 폭까지 줄어들어 배율이 진동한다. vw·vh는 zoom을 안 따라오므로 그걸 쓰는 규칙은 `calc(100vw / var(--zoom) …)`로 보정한다(사이드바 높이, 패널 열렸을 때 본문 max-width, 토스트 폭). 폰(<900px)은 배율 1 그대로.
- 폰 보드는 세로 스택이 아니라 **할일|진행중 2열 나란히**(kb-flat 그리드) + 완료는 접힌 목록. 상세는 grid-column 1/-1로 두 열을 가로질러 전체 폭. 세로로 죽 쌓으면 진행중이 화면 밖으로 밀려 "한눈에 안 보인다"는 지적을 받음 (2026-07-19).
- **화면 오류 안전장치 (2026-08-11)**: `src/components/ErrorBoundary.jsx`를 두 겹으로 쓴다 — main.jsx가 앱 전체를(`whole`, 백업 받기 버튼 포함), App.jsx가 화면마다(`key={screen}`이라 화면을 옮기면 오류가 저절로 풀림). 루틴을 넣다가 무한 렌더로 **로그인 화면조차 못 그리고 하얗게 남은 사고**가 계기. ⚠️ 리액트 안전장치는 **그리는 중의 오류만** 잡는다(이벤트 핸들러 오류는 못 잡음). 그리고 **`useSyncExternalStore`의 getter에서 filter·sort로 새 배열을 만들지 말 것** — 그게 그 사고의 원인이었다. 화면이 읽는 목록은 `withVisible()`에서 한 번 만들어 담아둔다(`visible`·`trash`·`routineList`).
